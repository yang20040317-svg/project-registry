## 一、唯一对外出口：manifest.json

```bash
registry.py export --root <项目根>        # 默认写 .project/registry/manifest.json
```

**铁律：外部工具一律吃 `manifest.json`，不许解析 `index.md`。**
`index.md` 是人读的（可加注释、可排版），机器解析它迟早会因为一次格式调整全崩；`manifest.json` 是契约，schema 固定：

```jsonc
{
  "schema": "project-registry/manifest@1",
  "project": "项目名",
  "positioning": "一句话定位",
  "type": "code-ui",
  "scale": "M",
  "generated": "2026-09-24T10:20:00",
  "assets": [
    { "id": "UI-001", "type": "UI", "name": "持仓资产卡片",
      "alias": ["资产卡", "position card"], "path": "src/components/AssetCard.tsx",
      "status": "在建", "deps": ["API-003"], "decisions": ["ADR-001"], "updated": "09-24" }
  ],
  "decisions": [
    { "id": "ADR-001", "title": "排序下移到服务端", "status": "生效",
      "decision": "排序下移到 API-003。", "assets": ["UI-001", "API-003"],
      "file": ".project/memory/decisions/ADR-001-sort-server.md" }
  ],
  "openLoops": [ { "item": "API-003 未定义", "blocked": "", "assets": [] } ]
}
```

**schema 演进**：改字段就升 `schema` 版本号（`@2`），消费方按版本分支，不静默改语义。

配套的第二个机器出口是 **`diff` 的 delta.json**（`registry.py diff a.json b.json --json delta.json`）——
它带**不含时间戳的收据哈希**，可以直接当「这一刻架构是什么样」的可核验凭证交给外部工具或评审。

## 二、留给外接的是哪一档（只看结论，机制见 05）

**三档精度的权威对照表在 `modules/05` §七**，本节不复述——同一张表写两处，迟早各说各话
（这正是 ADR-002 要裁的东西）。这里只留接入决策要用的结论：

- `reconcile`（**文件级**）与 `scan`（**导入级**）**都已内置、零依赖、纯本地**
- 外接只发生在**这两档答不了**的时候：**符号级** → Serena（见 §三）
- 三档是**精度递增**，不是替换关系：先把内建两档跑顺，再谈外接（顺序见 §七）

## 三、Serena（符号级代码理解）· 只补 `scan` 够不到的那一半

Serena 是 MCP 符号级工具包（默认 LSP 后端，40+ 语言，`find_symbol` / `find_referencing_symbols` /
跨文件重命名为原子调用）。安装：`uv tool install -p 3.13 serena-agent`，再配到 `~/.workbuddy/mcp.json`。

### 它给内核什么（`scan` 给不了的）

- **符号级对账**：`scan` 只能看到「`src/ui/card.ts` 导入了 `src/api/client.ts`」；Serena 能看到
  「这个函数属于哪个模块、被谁调用」→ 与 manifest 的 `assets[].path` 对账，能发现
  「声明的依赖和代码实际依赖不一致」**在函数粒度上的版本**。
- **改动影响面**：`find_referencing_symbols` 直接回答"动它要动几处"——这是估工期的真实依据。
- **重构类操作**：跨文件重命名、安全删除、继承/实现查找。这些没法用正则做。

### 划界铁律（不划清必翻车）

**Serena 自带一套 memory 系统**（跨会话读写项目记忆）。两套记忆并存会漂移。规定：

| 内容 | 归属 |
|---|---|
| 工具操作便签（怎么 build、语言服务器怎么配、踩过的 LSP 坑） | Serena memory |
| **项目事实 / 资产身份 / 决策 / 会话结论** | **`.project/`（唯一）** |

判定一句话：**"三个月后还要不要记得"——要，就写 `.project/`**。

### 接法（建议最后接）

1. 先让 `reconcile`（文件级）与 `scan`（导入级）跑顺 —— 它们零依赖，是所有上层的基础
2. 再让 Serena 补符号级：`find_symbol` 结果 → 与 manifest 的 `assets[].path` 对账
3. **Serena 只读不写注册表**：它的输出先进 `proposals.md`，不直接改 `index.md`

## 四、Archify（多视图呈现）· 只负责呈现

Archify 是把意图变成**可交互图**的技能（typed JSON IR + 图内校验 + Architecture Delta 对比 + SRC 证据节点绑 Git commit）。
本技能只有「架构图」一种视图；需要**时序 / 工作流 / 数据流 / 生命周期**图时才值得叠加。

### 位置纠正（关键）

它在链路里的正确位置是**最后一环的沟通产物**，**不是代码校验源**：

- 它校验的是**它自己生成的图**（schema 合法、布局不重叠、标签不压线），**不扫描你的代码库**。
- 图里的依赖事实是 agent 读了仓库后 **authored** 进 IR 的——事实从哪来？**从 `scan` / `reconcile` / Serena 来**。
- 所以"依赖违规检测"这件事，**前半段（事实）归 `scan` / Serena，判定（法则）归 `audit`，
  呈现与图校验收归 Archify**。不要指望它替你分析 src，也别指望它知道你的层间规则。

### 接法

```
manifest.json（资产 + 依赖 + 决策）
   → 由 agent 转成 Archify typed IR（节点=资产 ID，边=依赖；违规边标 `violation`）
   → Archify 渲染 + 图校验 + delta 对比
```

**delta 的高价值用法**：`diff` 已经能出「这段时间架构变了什么」的文本与收据；
需要**交互式 delta 视图**（可点开的 Before / Delta / After）时，把 `delta.json` 一并交给 Archify。
配上同期 ADR，就是一份**可交付的架构演进说明**——这是注册表最容易变现的输出。

## 六、自动化扫描 · 对账器（`reconcile`，已内置）

```bash
registry.py reconcile --root <项目根> [--ext .ts,.tsx] [--write]
```

### 它比"行数统计"多做的事

| 提议类型 | 含义 | 为什么值钱 |
|---|---|---|
| **未登记** | 代码里有，注册表没有 | 抓幽灵代码、抓"偷偷加的模块" |
| **失效登记** | 注册表有，代码里没了 | 抓删了没销账的僵尸条目 |
| **命名违规** | 语义名命中禁用词 | 抓"新的/优化版/v2"这类会腐化的名字 |
| **疑重** | 注册项之间名称近似 | 抓"同一个东西登记了两遍" |

（行数统计与增量扫描归 `scan`，见 `modules/05`。）

### 提议权 ≠ 裁决权（最重要的一条）

- 机器**只能**写 `registry/proposals.md`（`--write` 时把未登记项追加进 open-loops）
- 机器**绝不**直写 `registry/index.md`
- 裁决发生在**收工**，由人（或收工时的 AI 逐条确认）

理由：机器直写注册表，一个月之内表就会变成"扫描结果的复制品"——而注册表存在的意义恰恰是
**人的判断**（这东西叫什么、跟邻居差在哪）。**`audit` 出的违规同理**：它说"规则拒绝了这条边"，
但"改代码还是改规则"必须由人裁决，并写进 ADR。

### 扫描范围

默认跳过 `.git / node_modules / dist / build / .next / venv / __pycache__` 等；默认扫主流代码后缀。`--ext` 可覆盖（如只看 `.py`）。

## 七、分阶段接入顺序

| 阶段 | 做什么 | 依赖 | 验收 |
|---|---|---|---|
| **1 内核 + 对账** | `init` → 登记资产 → `reconcile` 跑顺 → `export` 出 manifest | 零（纯本地） | `check` 0 错；`reconcile` 提议被逐条裁决过一轮 |
| **1.5 导入级理解** | `scan` → `imports.json`；补/删注册表的 `依赖` 列 | 零（纯本地） | 「漏声明 / 多声明」逐条裁决过；行数与自己数的量级一致 |
| **1.6 架构校验** | `audit --init` → 收紧 `rules` → `audit --strict` | 零（纯本地） | 规则配完**至少报出一条**（报 0 条先怀疑规则写反）；违规逐条裁决 |
| **2 出图 + 演进** | `viz` / `graph` / `diff` | 零（纯本地） | 图能开；节点数 = 资产数；六项体检与 `audit` / `graph` 报同一个值；两次 export 出 delta |
| **3 接 Serena** | 符号级事实 → 符号级对账、影响面分析 | Serena（MCP + LSP） | 注册表 `依赖` 与真实导入一致；改动影响面可回答 |
| **4 接 Archify** | manifest + delta.json → IR → 多视图 / 交互 delta | Archify | 图节点 = 资产 ID；违规边被标出；两次 export 能出交互 delta |

**不要跳阶段**：先上 Archify 会得到一个漂亮但事实空洞的图；先上 Serena 而注册表空着，
等于让符号扫描结果反过来当身份——顺序反了。
