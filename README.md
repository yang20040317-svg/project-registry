# project-registry

[![tests](https://github.com/yang20040317-svg/project-registry/actions/workflows/test.yml/badge.svg)](https://github.com/yang20040317-svg/project-registry/actions/workflows/test.yml)

> 给项目里每一个「东西」发唯一身份，并把「为什么这么定 / 上次聊到哪」沉淀成可续的上下文。

> **不知道怎么用、用在哪？** → 先读 **[USAGE.md](USAGE.md)**：它有什么用（五个真实痛点）、
> 什么项目值得用、一个完整场景从开工走到收工（终端回显全部来自实跑）。

> **一件事做完时，它会主动提醒你开新对话**，并顺手给一段可直接粘贴的开场白（项目根 + 开工第一读 +
> 上次起步点 + 最堵的开环）—— 不必为了「怕丢上下文」把一条对话越拖越长。（`close` 末尾自带，`--no-tip` 可关。）

**是**：一套让项目「不失名、不失忆」的机制。
**不是**：排期表、甘特图、任务看板、Code Review 工具、代码规范检查器。

代码只是这套机制的载体之一。一个**写作项目**的章节、一个**研究项目**的假设、一个**设计项目**的视觉件，
同样需要唯一身份与可续记忆 —— 本技能按「项目类型」路由资产维度，机制不变。

## 它解决什么

| 症状 | 本技能怎么治 |
|---|---|
| 同一个模块被起了几个名字 / 同一个 UI 做了两遍 | **命名注册表**：ID + 语义名 + 别名，`add` 时三查查重（同名 → 同义 → 同职责） |
| 「上次为什么这么定」没人记得 | **决策卡（ADR）**：决策引用资产 ID，资产卡反查决策 ID |
| 「上次聊到哪」接不上 | **上下文包 + 开环**：开工第一读，收工必沉淀 |
| 一件事做完了，却不敢开新对话（怕丢上下文），于是一条对话越拖越长直到被压缩 | **收工交接提示**：`close` 末尾主动提醒你开新的，并给可直接粘贴的开场白（项目根 / 第一读 / 起步点 / 最堵开环） |
| 代码里哪些是幽灵 / 哪些没登记 | `scan` + `reconcile`：导入级依赖图 + 只提议不裁决的对账 |

## 双引擎

```
引擎 A · 命名注册表（Registry）   →  项目里每个「东西」有唯一身份
    ID（机器键） + 语义名（人读） + 别名（俗称） + 路径 + 状态 + 依赖 + 决策
        ↕ 用同一个 ID 互相咬合
引擎 B · 记忆层（Memory）         →  项目「为什么这么定 / 上次聊到哪」可续
    L1 会话记忆 / L2 决策记忆(ADR) / L3 项目记忆(上下文包) + 开环
```

**为什么必须双引擎**：只做注册表 → 记得住「叫什么」，记不住「为什么」；只做记忆 → 记得住「聊过什么」，
但同一个东西仍会被做两遍。两者靠 ID 咬合才闭环。

## 快速开始

零依赖 —— 只用 Python 标准库，不需要 `pip install` 任何东西。

```bash
git clone https://github.com/yang20040317-svg/project-registry.git

# 30 秒：一行起项目并登记第一条资产
# （当前目录没有 .project/ 就先自动建 L 档轻量项目）
python project-registry/scripts/registry.py quick "登录页" --type UI
```

`quick` 是**单行引导入口**，不是新机制：底层仍走全部命名 / 查重 / 前缀闸门，只是把 `init` + `add`
两次仪式压成一行。项目长大后再回到三步工作流即可。

作为技能使用时，把整个目录放到宿主的技能目录（例如 `~/.workbuddy/skills/project-registry/`），
宿主按 `SKILL.md` 的 description 触发加载。

## 三步工作流（开工 → 过程 → 收工）

**第 1 步 ｜ 开工：先读上下文包，再动手**
读 `.project/memory/context-packet.md`（没有就 `init` 建项目）。它回答四件事：项目是什么、现在到哪、
活跃资产有哪些、卡在哪。**没读就开工 = 失忆开工。**

**第 2 步 ｜ 过程中：三道闸门**
- **命名闸门**（新建任何东西前）：先查重 → 命中就复用，确需另起则先分配 ID 再动手。还没落盘的用
  `--status 构思`（位置可只写意向）。
- **决策闸门**（非显然的决定）：「选了 A 而不是 B」「改了之前的定法」「划了不做的边界」→ 当场写决策卡。
- **架构闸门**（跨层依赖动过之后）：`audit` —— 代码里的实际依赖是否违反声明的层间规则。

**第 3 步 ｜ 收工：必沉淀**
`close --summary "..."`，或手工三步：追加会话记录 / 更新受影响注册项 / 刷新上下文包 + 登记开环。
`close` 会顺手做一次**收工体检**（登记了却没交代的四类），只提示不阻断。
末尾还会给一段**交接提示**：提醒你开新对话，并附上可直接粘贴的开场白（项目根 + 开工第一读 +
上次起步点 + 最堵的开环）—— 让「开新对话」不再需要勇气。`--no-tip` 可关掉。

## 命令速查

| 命令 | 作用 |
|---|---|
| `init` | 建项目：身份卡 + 类型 + 规模分档 + 骨架 |
| `quick` | 一行起项目并登记第一条资产（轻量上手） |
| `add` / `set` / `retire` | 登记 / 改资产 / 弃用（弃用要写原因） |
| `find` / `list` | 按词、按类型、按状态检索资产 |
| `check` | 一致性闸门：路径存在、ID 唯一、决策引用有效、开环有归属、依赖状态合法 |
| `context` | 生成/刷新上下文包（开工第一读） |
| `close` | 收工沉淀 + 收工体检 + 交接提示（提醒开新对话 + 可粘贴开场白） |
| `loop` | 开环台账：`--list` / `--done` |
| `idseq` | ID 单调游标：保证 ID 永不回收 |
| `export` | 导出 `manifest.json`（机器可读出口） |
| `reconcile` | 磁盘 ↔ 注册表对账，**只提议不裁决** |
| `graph` / `viz` | 依赖图 / 自包含架构图 HTML（零依赖双击即开，违规边标红） |
| `scan` | 导入级代码理解：import 依赖图 + 有效行数 + 声明与实际对账 |
| `audit` | 架构校验：层间规则 + 循环 + 出度 + 未归类（`--strict` 接 CI） |
| `diff` | 两份 manifest → 架构演进 + 机器收据（同内容必得同收据） |

## 闸门与退出码

**机器闸门**（有退出码，能被脚本 / CI 拦住）：

| 闸门 | 命令 | 触发 | 退出码 |
|---|---|---|---|
| 命名 + 查重 | `add` | 前缀未定义 / 语义名命中禁用词 / 查重命中 | `2` |
| 一致性 | `check` | 路径不存在 / ID 重复 / 决策引用悬空 / 开环无归属 / 依赖了「废弃」 | `1` |
| 架构 | `audit --strict` | 层间违规 / 循环依赖 / 出度超限 | `3` |

表里没写的东西就不是闸门。另有**纪律闸门**（无机器执行者，靠流程守）：决策卡该写、收工该沉淀、
过程中的主动登记提醒 —— 这些是节奏判断，机器守不了。

几条刻意的设计取向：
- **只提议不裁决**：`reconcile` 写 `proposals.md`，绝不直写 `index.md`。机器直写一个月，注册表就变成扫描结果的复制品。
- **先登记再动手**：`构思` 状态的资产享受路径校验豁免（位置还只是意向），否则第一步就被自己的闸门卡死。
- **无事实可判必须说出来**：`audit` 在没有任何依赖边时必然 0 违规、rc=0 —— *看起来通过了*。所以此时终端与报告都会显式打一行「本次无事实可判」，绝不做静默的绿。
- **并发写是安全的**：所有写命令在 `.project.lock` 上取互斥锁，「读 → 改 → 写」是一个事务；两个终端同时 `add` 不会各发一次 `UI-001`。等不到锁（默认 20 秒）**直接报错**，而不是偷偷写坏。

## 落盘结构

全部落在**项目根**，不在技能目录：

```
<项目根>/.project/
├── PROJECT.md                  # 项目身份卡：一句话定位/类型/规模/阶段/边界
├── architecture.json           # 架构规则：层定义 + 允许/禁止的层间边
├── registry/
│   ├── index.md                # 资产总表（人读）
│   ├── manifest.json           # 同一份数据的机器可读出口
│   ├── proposals.md            # reconcile 的对账提议（只提议，不裁决）
│   ├── naming.md               # 命名约定 + 自定义维度（§四 是前缀定义处之一）
│   ├── entities/               # [F 档] 每个资产一张详卡
│   └── .idseq.json             # ID 单调游标：保证 ID 永不回收
└── memory/
    ├── context-packet.md       # 开工第一读
    ├── sessions/ decisions/    # 会话记录 / 决策卡 ADR
    ├── open-loops.md           # 未闭环事项
    └── log.md                  # [L 档] 单一流水
```

**规模分档**（管理本身不许臃肿）：`L` 轻量（资产 < 15、单人、短周期，会话与决策混记）/
`M` 标准（默认，拆开会话与决策）/ `F` 完整（加详卡与依赖图）。

## 模块索引

- `USAGE.md` — 怎么用 · 有什么用：五个真实痛点、什么项目值得用、一个完整场景走一遍（真实终端回显）
- `SKILL.md` — 总控与索引（行为协议、三步工作流、闸门总表）
- `modules/01-项目身份.md` — 身份卡、类型选定、规模分档、边界声明
- `modules/02-命名注册表.md` — 引擎 A：ID 规则、命名三问、查重三查、状态机、别名收敛
- `modules/03-记忆层.md` — 引擎 B：三层记忆、上下文包结构、决策卡、开环
- `modules/04-外部接入.md` — 只做指针：接入协议、manifest / delta schema、外接决策
- `modules/05-代码理解与架构校验.md` — `scan` / `audit` / `diff` / `viz` 的机制权威
- `references/project-types/` — 各类型的资产维度定义（代码 UI / 写作内容 / 研究调研 / 自定义）
- `references/templates/` — 落盘模板
- `scripts/registry.py` — 全部命令的实现（单文件，stdlib only）

> 子模块文件是权威源；`SKILL.md` 是总控与索引。
