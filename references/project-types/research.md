# 维度定义 · 研究 / 调研项目（type: research）

| 前缀 | 维度 | 什么东西算一个 | 字段提示 |
|---|---|---|---|
| `Q` | 研究问题 | 一个要回答的问题（可拆子问题） | 一句话，能判"答完没有" |
| `H` | 假设 | 一个待检验的猜想 | 必须可证伪，否则打回 |
| `DS` | 数据源 | 一份数据 / 一个样本 / 一个信息渠道 | 记获取方式与时效 |
| `MTH` | 方法 / 实验 | 一次分析做法或实验设计 | 换了做法就新登记 |
| `FND` | 发现 | 一条从数据里得出的观察 | 与 H 分开：发现是事实，假设是猜想 |
| `CON` | 结论 | 一个可交付的判断 | 必须指回它回答的 Q |
| `AST` | 产出物 | 图表、报告、附录 | 与 code-ui 的 AST 同前缀、同义 |

## 常见命名陷阱（本类型特有）

- **发现与结论混淆**：`FND` 是"数据显示 X 与 Y 相关"，`CON` 是"因此建议做 Z"。混在一起会让结论失去依据。
- **结论悬空**：CON 没有指回任何 Q → 说明做了个没人问的结论。
- **假设不可证伪**："用户可能更喜欢简洁界面"不是可操作假设 → 改成"在 A/B 中版本 B（更少元素）的完成率更高"。
- **数据源不记时效**：过期的 DS 被继续引用是研究报告最常见的暗伤。

## 依赖写法

`CON-002 依赖 Q-001, FND-005, FND-007`。
一条结论**至少**挂一个 Q 和一个 FND，否则 `check` 会告警。
