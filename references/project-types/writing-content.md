# 维度定义 · 写作 / 内容项目（type: writing-content）

| 前缀 | 维度 | 什么东西算一个 | 字段提示 |
|---|---|---|---|
| `CH` | 章节 / 篇 | 一个可独立阅读的单元 | 职责句写"这一节让读者得到什么" |
| `ARG` | 论点 / 主张 | 一条要论证的观点 | 与 `CH` 是多对多，别合并 |
| `MAT` | 素材 | 案例、故事、数据、引语、图 | 素材可复用，用完标"已用于 CH-00x" |
| `SRC` | 来源 / 引用 | 一本书、一篇文献、一次访谈 | 合规要害：必须能回溯 |
| `DR` | 稿件版本 | 一次成稿 / 一轮改稿 | 只登记有意义的版本，不登记每次保存 |
| `OUT` | 大纲 / 结构 | 整体骨架（通常只有 1 个） | 改大纲常牵动多个 CH |

## 常见命名陷阱（本类型特有）

- **素材与来源混淆**：`MAT` 是内容本身，`SRC` 是它从哪来。同一段话被三个来源提到 → 一条 MAT + 三条 SRC。
- **版本当新章节**：改稿是 `DR` 的新条目，不是 `CH` 的新条目。改到结构变化才动 CH。
- **论点漂移**：同一主张在不同章节换了说法 → 收敛到一条 `ARG`，别名表记下几种说法。
- **未使用素材堆积**：MAT 超过 20 条且多数未用 → 开环裁决"用还是弃"。

## 依赖写法

`CH-003 依赖 ARG-002, MAT-011, SRC-004`。
论证链比依赖链更重要：在决策卡里记"为什么这个论点放在这章"。
